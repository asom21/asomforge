# 多模型连接配置与连通性测试设计

<!-- 约定模型连接、模型目录、协议适配和真实文本连通性测试的范围。 -->

状态：用户已确认并授权实现；2026-11-25。独立设计检查已完成，未发现影响实施计划的未决问题。此前已确认一份连接管理多个模型、借鉴 DeepSeek Harness 的编辑方式，并允许使用指定消息发送真实推理请求。

## 1. 目标与已讨论的方案

将“大模型”资源从单一模型地址升级为“一个 API 连接 + 多个可选模型”。配置中心仍保存本地文件，API Key 与普通配置分离，前端不保存凭据到 localStorage。保留现有居中弹窗、单内容滚动区和深浅主题。

讨论并选择的方案：一个连接下管理多个模型，连接负责地址、协议和凭据，各模型负责能力声明和推理档位。相比每个模型重复一份地址/密钥，减少重复维护；相比只扩展现有单模型表单，能为后续 Agent 选择不同模型提供明确目录。用户已同意采用。

当前阶段实现配置、模型发现和明确点击触发的文本测试。不接入 Agent 执行引擎，不修改 Codex、Claude Code 或 DSH 的配置；不提供工具调用、浏览器或文件访问；不引入数据库和模型 SDK 大依赖。

## 2. 界面与操作

大模型列表的一行代表一个连接，显示连接名称、协议/地址摘要、模型数、启用状态和最近测试摘要。模型数不会与左侧连接数混淆。

居中编辑弹窗分为：

1. 基础连接：显示名称、说明、API 地址、API 协议、API Key。协议明确为 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages。
2. 模型目录：手动添加、获取可用模型、默认模型选择。每个模型行显示模型 ID、显示名称、测试结果、展开/删除操作；ID 是实际发送给 API 的 model 字段，显示名称仅用于界面。第一个模型默认选中，也可更改默认模型。
3. 展开的模型详情：上下文窗口、最大输出 token、文本/图片输入声明、推理档位开关及档位到 API 值的映射。
4. 每个模型的“测试连接”：使用当前表单中的连接和该模型 ID；可选择已声明的推理档位，默认“接口默认”（不发送推理参数）。展示测试消息、少量 token 消耗提示、开始/取消、状态、耗时、时间及受限长度的文本响应。

模型能力默认收起；文本输入默认开启。容量允许正整数和十进制 K/M 简写，128K=128000、1M=1000000；空白表示未声明，不暗示模型有某个默认容量。不以获取列表成功推断图片或推理能力。

模型列表页的“检查”打开模型选择与测试弹窗，默认选中该连接的默认模型；一次只测试一个模型。不提供隐藏的全目录批量付费测试。

## 3. 配置结构与校验

沿用 Resource 的 ID、revision、enabled 和凭据引用。ModelConfig 使用：

- `protocol`: `openai-chat-completions` / `openai-responses` / `anthropic-messages`。
- `base_url`: HTTP/HTTPS 协议根地址，允许中转与 localhost；禁用 URL 内嵌用户名/密码。
- `api_key`: 保存前输入，普通响应为空，真实值继续存入私密文件。
- `output_token_field`: 仅 Chat 协议可用，`max_completion_tokens`（默认）或 `max_tokens`（兼容旧端点）；切换其他协议时不发送该字段。
- `models`: 非空模型条目数组，新建或修改时至少一个模型；ID 去除两端空白后非空且连接内唯一。
- `default_model_id`: 必须指向目录条目，未指定时取第一个。

每个模型条目：`id`、可选 `name`、可选 `context_window`、可选 `max_output_tokens`、`input_modalities`（text/image）、可选 `reasoning_efforts`（false 或档位到字符串/空值的映射）。容量为严格正整数；两者均指定时输出上限不得超过上下文窗口。输入类型至少一个，本轮文本连通性测试要求支持 text。

推理档位允许 off/minimal/low/medium/high/xhigh，提供商不支持的档位不添加。启用后至少一个非 off 档位，避免重复档位。非 off 映射值必须为非空字符串。off 可填写提供商要求的关闭值；off 空值明确表示不发送推理参数，不声称端点一定关闭思考。界面将其解释为“使用接口默认参数”。关闭档位编辑时保存 false；未声明时不假定能力。

结果作为资源元数据保存，不写入模型定义：新增 `model_checks`，以模型 ID 索引结果，记录结果、测试模式、配置 revision、所用推理档位、时间、位置、耗时和必要的响应摘要。保存/启用切换按现有版本机制使旧结果失效；同一版本测试不同模型互不覆盖。

## 4. 模型发现

点击“获取可用模型”才连接端点；使用当前草稿中的地址、协议和新密钥，或按资源 ID/revision 解析已保存密钥。明确清除凭据时不使用旧密钥。获取失败保留草稿并允许手动添加。

- OpenAI 两种协议：GET `{base_url}/models`，Bearer 认证。
- Anthropic：GET 模型列表，原生根地址无 /v1 时追加 /v1/models；若基址已以 /v1 结束则追加 /models；使用 x-api-key 和 anthropic-version。
- 接受标准 data 数组及明确的 models 对象格式，过滤无效条目、按模型 ID 去重；只采纳响应实际提供的名称、容量等元数据，不从模型名称猜测能力。
- 结果作为候选列表，用户勾选后追加；相同 ID 不重复，不覆盖手工能力、默认选择和现有模型。取消选取不改草稿。
- 不支持模型列表发现不等于推理不可用；界面显示可继续手动配置和测试。

无远端内置目录依赖，不移植 DSH/pi-ai 全部提供商注册表和兼容开关。凭据不回传到候选结果、错误响应或日志。

## 5. 真实连通性测试

固定用户消息，逐字发送，不追加工作区内容、历史消息或工具定义：

> 请只回复：连接成功。不要执行命令或修改文件。

一次点击仅发送一个请求，无自动重试。由后端发 HTTP 请求，三个协议分别构造：

- Chat Completions：POST `{base_url}/chat/completions`，`messages` 含一条 user 文本。
- Responses：POST `{base_url}/responses`，使用对应 user 文本 input。
- Anthropic Messages：POST messages 路径，使用原生模型、messages、max_tokens 和认证头。

地址拼接保留用户的自定义前缀，不将 /codex 等地址改成其他根路径；校验提示输入协议根地址。Anthropic 的 /v1 规则与发现相同。

非流式接收远端响应，本地可通过 SSE 传达“测试中/结果”并响应取消。输出预算上限为 1024 token；模型明确声明更低上限时取较小值。Chat 默认使用 max_completion_tokens，Responses 使用 max_output_tokens，Anthropic 使用 max_tokens；遇到不兼容参数明确提示，不暗中删参或重试以免增加消费。允许测试框在 Chat 模式选择兼容旧接口的 max_tokens 字段，此选择属于连接配置并使旧结果失效。显式选择的推理档位按协议映射：Chat reasoning_effort，Responses reasoning.effort；Anthropic 暂不承诺通用推理档位映射，选择该协议时隐藏档位编辑并拒绝非空档位映射，已存在的映射须显式移除后再保存。

返回判定：

- 收到合法协议文本且内容去除首尾空白和末尾句号后为“连接成功”：passed。
- 收到其他非空文本：limited，明确“已收到模型回复，但未按约定返回连接成功”，提供不超过 240 字符的摘要。
- 输出预算耗尽且无文本、空响应或工具调用响应：limited，说明本次未确认文本回复；工具调用内容从不执行。
- 认证、模型不存在、协议/路径、请求参数、限流、超时、DNS/TLS/连接故障分别给出可操作的失败原因；服务端异常统一脱敏，不回显请求头、密钥和远端原始错误体。

不把上述文本调用外推为图片输入、最大上下文或全部推理档位已经验证。端点不发布模型列表时仍可单独测试。

## 6. 草稿、已保存版本与取消

模型发现及模型测试支持草稿，避免必须保存后才能判断地址。请求包含当前完整连接草稿和可选资源 ID/revision，指定模型 ID 及可选推理档位；后端按版本解析已存凭据，拒绝过期引用，不由浏览器传递私密值。资源 ID 必须确实属于 models 类型。

草稿测试不自动保存配置、凭据或结果。结果在弹窗中临时显示；修改影响调用的地址、协议、凭据、模型 ID、容量、推理参数等后，前端标记结果已过期。保存草稿后需要对已保存版本重新测试，不把旧草稿结果冒充为保存版本的结果。

列表中的已保存模型测试按资源 ID、revision、模型 ID 执行。只有资源版本仍相同时才登记 `model_checks` 和 `last_check`；删除/修改资源后，不让旧测试写回或覆盖新版本。last_check 只代表最近一次指定模型的结果，文案明确“最近测试：模型名”，不代表整份目录都通过。

复用现有检查超时和并发配置（默认总时限 20s、并发 3，包含排队）。点击取消、关闭窗口或断开请求时，取消本地 HTTP 请求、不登记取消结果；提示远端可能已处理并产生少量费用。非必要时不持有文件事务锁跨越网络等待。

## 7. 资源、响应与兼容边界

发现和测试均限制远端实际读取响应体（含解压后）不超过 4MiB；默认不跟随重定向，防止密钥被转发。由已有本机 API 边界与 Pydantic 校验接入，错误提示不包含原始敏感请求。

旧配置读取时兼容 `openai`（映射 Chat）、`anthropic`（映射 Messages）和单 `model` 字段，形成一个目录条目。保留资源 ID、revision、启用及凭据引用，读取不重写磁盘；用户保存时写新结构。旧 model 为空时仍可展示连接，但标为目录待补全，不能直接测试；编辑保存需补上至少一个模型。导入同时接受旧格式和新格式，不复制历史测试状态。

旧 last_check 的模型发现结果只显示“历史模型列表检查”，不标为真实连通性已通过。其他资源的检查行为保持原样。既有 /check 模型入口默认检查默认模型的真实文本调用，前端按钮文案明确提示请求范围。

## 8. 工程落点与验收

- 领域：增加连接/模型条目、请求/候选/结果校验及旧字段规范化。
- 应用层：草稿凭据解析、版本校验、模型结果登记。
- 运行时：独立模型 HTTP 适配器，协议请求/响应、发现、响应上限与取消。
- API：模型发现和模型测试入口；复用 SSE 生命周期；同步导出 OpenAPI 和前端类型。
- 前端：独立模型连接编辑组件、目录候选选择、每模型能力表单和测试状态；不继续扩张通用字符串 Values 以容纳嵌套结构。
- 文档：更新配置中心说明、模型导入示例、README 检查范围、技术路线；默认端口继续前端 3000/后端 8000。

测试使用受控本地 HTTP 服务验证三种协议真实请求路径/消息/认证/参数、候选发现、错误码、响应上限、无工具、无自动重试、超时取消、草稿不落盘、凭据不泄漏、版本竞争、旧格式导入与更新。浏览器验收多个模型添加/展开/删除/默认选择、容量简写、重复 ID、发现失败仍可填写、测试结果失效、深浅主题和单滚动区。运行 pytest、Ruff、前端类型/格式/构建和相应浏览器检查。

实施验证不会擅自使用用户现有密钥调用外部付费模型；受控服务先覆盖真实 HTTP 流程，用户点击测试时才请求其端点。
