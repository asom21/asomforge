## 1. 交付目标

完成一个个人本地使用的配置中心，包含前端、后端、本地文件保存、导入校验和适用的可用性测试。用户能够导入或新建配置，查看列表，编辑、保存、删除，并在刷新页面或重启服务后重新读取。

资源包括 Skill、MCP、Prompt、大模型和运行平台。Tool 在导航中显示“暂未开放”，保留目录，不提供配置读写或执行接口。

本阶段不建设用户体系、数据库、画布、Agent 执行、定时调度、恢复引擎、客户端全局配置同步或模型请求代理。后续支持多链路并发，同一平台可被多个 Agent 使用；当前资源通过稳定 ID 引用，不承担执行状态和占用锁职责。

项目已有约定见 [AGENTS.md](../../../AGENTS.md)、[本地数据目录](../../../doc/README.md)和[技术路线](../../decisions/technology-direction.md)。

## 2. 技术与组织方式

本阶段采用以下实现方向，具体兼容版本在初始化时核对并通过锁文件固定：

| 部分 | 选择 |
| --- | --- |
| 前端 | TypeScript、React、Vite；共用页面骨架，各类型使用自己的表单 |
| 后端 | Python、FastAPI、Pydantic；一个本地后端服务 |
| 存储 | 后端统一读写 JSON 和 Skill 目录，不引入 ORM 或数据库迁移工具 |
| 协议与连接 | 使用官方 MCP Python SDK 和 HTTP 客户端；运行平台分别提供小型检测适配器 |
| 工具链 | pnpm、uv；前端使用统一格式化工具，Python 使用 Ruff |
| 接口类型 | 从后端 OpenAPI 生成前端接口类型，业务校验以服务端为准 |

后端沿用现有目录：api 处理协议，application 放保存、导入和测试用例，domain 放资源规则及窄接口，infrastructure 实现文件与凭据保存，runtimes 放平台检测。没有对应职责时不增加空类或转发层。

前端在 features/configuration 中按页面组合、类型表单、导入和测试结果等实际职责组织。通用按钮、表单项和弹层按实际复用提取，不先建设动态表单引擎；紧密相关的小逻辑保留在同一文件。

## 3. 界面与操作

左侧为固定分类导航，右侧为配置内容区。分类顺序为 Skill、MCP、Tool、Prompt、大模型、运行平台。界面使用统一字体与间距、明确的主次层级和克制的强调色；先完成一套一致的视觉样式，不建设主题管理系统。

内容区包含名称搜索、新建、导入、配置列表；列表显示名称、摘要及最近检查结果。选择配置后查看详情，新增与编辑使用侧边编辑区。不同类型使用明确的字段表单，MCP 另提供 JSON 查看与编辑入口。

保存与检查是独立操作：静态校验在保存前执行，保存失败保留表单内容；连接测试由用户明确点击发起，不随导入、保存或应用启动自动运行。编辑后尚未保存的内容不沿用上次检查结果。离开有未保存内容的编辑区时提醒用户。

导入采用“选择文件或目录 → 解析和校验 → 预览条目及冲突 → 用户选择处理方式 → 保存”。默认保留已有同名资源，用户可以明确选择替换或另存；替换保留原资源 ID，另存生成新 ID。Skill 的显示名称与标准包名分别处理，不能通过简单改目录名破坏包内引用。

## 4. 资源字段与导入范围

普通资源使用共同的登记字段：schema_version、id、name、description、revision、created_at、updated_at，以及按类型校验的 config。ID 不随显示名称变化；revision 用于区分修改及检查结果，不代表已建设历史版本回滚能力。

| 资源 | 专属内容 | 导入方式 | 检查范围 |
| --- | --- | --- | --- |
| Skill | 标准包名、说明、SKILL.md、配套文件及平台登记信息 | 本地目录或 ZIP，完整保留包内结构 | SKILL.md、frontmatter 必填字段及名称规则、包内文件结构与引用 |
| MCP | 连接类型、command、args、env 或 url、headers，以及可选工作目录 | 常见 mcpServers JSON，可从文件导入或粘贴 | 来源结构、字段类型、必填项、支持的传输与实际连接 |
| Prompt | 正文、变量声明 | Markdown、纯文本或本平台资源 JSON | 正文、变量名称及模板中使用的变量；使用简单的双花括号变量，不引入模板执行引擎 |
| 大模型 | 接口协议、base_url、凭据引用、模型标识 | 本平台资源 JSON | 地址和配置结构；按协议读取模型列表，区分连接、鉴权和模型发现结果 |
| 运行平台 | 平台类型、启动命令与参数、凭据引用、可选默认工作目录 | 本平台资源 JSON | 程序可用性、版本与平台实际提供的只读认证状态 |

大模型首期支持 OpenAI 兼容接口和 Anthropic 接口，DeepSeek 按所选兼容协议配置。模型连接测试不发送生成请求；端点不支持模型列表时明确显示本次检查的限制，不能因此宣称推理调用成功或直接认定配置无效。

运行平台类型为 Codex、Claude Code、DeepSeek Harness，同类型可以保存多份配置。平台默认工作目录是可选默认值，后续 Agent 节点可以指定自己的工作目录；配置中心不创建或接管平台的全局登录文件。

Skill 导入后由本平台目录管理，不修改来源目录。Skill 页面支持登记信息和 SKILL.md 的查看、编辑及配套文件列表，不建设通用多文件 IDE。Skill 标准包名与其内容根目录保持一致；普通显示名可以独立修改。

本平台资源 JSON 沿用上述登记结构。导入新资源时由后端生成 ID；只有用户明确选择替换，才更新已定位的本平台资源。导入中包含凭据值时分离到本机私密存储，预览与普通配置不回显凭据。

## 5. MCP 校验与连接测试

首期来源文件必须是合法 JSON，顶层包含对象类型的 mcpServers，每项对应一个有名称的服务器定义。不自动修复语法错误，不猜测其他客户端的 TOML 或 YAML 格式，不将非法字段静默改成空值。

| 连接类型 | 字段要求 |
| --- | --- |
| stdio | command 为非空字符串；args 如提供则为字符串数组；env 如提供则为字符串映射；工作目录如提供须能解析 |
| Streamable HTTP | url 为有效 HTTP 或 HTTPS 地址；headers 如提供则为字符串映射 |
| 旧版 SSE | 明确声明为 SSE，按旧版传输检测；不能与 Streamable HTTP 混用 |

未声明 type 时，根据 command 或 url 确定传输类型；两者同时提供或无法确定时报告歧义，要求用户选择。未知扩展字段在导入预览中明确提示，原始来源作为私有副本保留；可执行配置只纳入已支持字段，不能把未支持字段显示为已经生效。

服务端是最终校验入口。前端负责及时展示必填项和后端返回的字段错误，避免在多个层重复维护同一套规则。

连接测试通过 MCP SDK 按支持的协议版本连接，并查询已声明的工具或资源能力；不执行服务器暴露的工具。连接、能力发现和具体工具执行分别表达，不能将连接成功等同于业务可用。

检查设置有统一的可配置超时和并发上限，支持取消；完成、取消或超时后释放本次创建的连接与子进程。结果关联资源 ID、revision、测试工作目录和时间。不直接记录或返回子进程原始输出、请求头及传输异常全文，提供检查阶段、错误类型和脱敏摘要。

MCP 自身支持某种传输，并不代表三种运行平台都支持。平台适配范围分别记录；对尚未支持的组合如实报告，不自动转换成另一个传输。

## 6. 运行平台检测范围

| 平台 | 本阶段检测 | 说明 |
| --- | --- | --- |
| Codex | 配置的程序能否找到、版本、已有认证状态的只读查询 | 参考 CLI 与 App Server 的公开接口；不启动 Agent 任务 |
| Claude Code | 配置的程序能否找到、版本，以及该版本支持的认证状态查询 | 检测能力按实际 CLI 接口实现，不通过改写全局配置来测试 |
| DeepSeek Harness | 配置的程序能否找到、版本或受支持的诊断、所需配置与凭据引用 | 官方仍处于开发者预览；SDK、CLI 与版本能力分开处理 |

只有实际完成的检查才显示通过。没有认证查询接口时，结果明确为“仅确认安装和配置，认证未验证”。未安装程序正常显示“未安装或路径不可用”，不自动安装或假装测试成功。

目前只读环境检查发现 Codex 和 Claude 命令在 PATH 上可见，dsh 未在 PATH 上发现；这不是对配置正确性、认证成功或 SDK 安装状态的验证。

## 7. 文件与凭据保存

沿用固定的 doc/config/skills、mcp、prompts、models、platforms、tools，以及 doc/private/ 和 doc/logs/。数据根目录只在后端入口配置，默认项目根目录的 doc/，允许通过本机启动配置覆盖。

普通资源以 ID 命名，每条一份 JSON。Skill 使用独立资源目录保存 resource.json 登记信息，并在其中保留以标准包名命名的内容根目录及 SKILL.md、scripts、references、assets 等材料；资源 ID 不取代标准 Skill 包名。

使用同目录临时文件写入，再替换目标文件，避免配置写到一半。Skill 多文件导入先完成解析和准备，再切换到目标资源目录；替换失败保留原资源。批量导入按条目报告成功、跳过和失败，不承诺跨所有资源的文件事务。

凭据保存在 doc/private/ 下的私密 JSON，普通配置只记录引用；不返回密钥占位符作为真实值。编辑时省略凭据表示保留，显式移除表示清除。私密值不进入普通响应、导入预览、检查结果或日志。实际数据均被 Git 忽略。

配置写入由单个后端实例协调。并发修改同一资源时核对 revision，冲突返回明确错误；不引入分布式锁、跨机器同步或自动重试写入。相对资源路径按其明确的资源根目录或所选工作目录解析，不依赖后端碰巧所在的当前目录。

导入文件与 ZIP 的目标路径限制在该资源目录内；导入及预览不执行文件中的命令或脚本。文件损坏、路径不可用和读写失败需要明确显示，不通过空列表或默认对象隐藏问题。

## 8. 接口与错误处理

使用一组按资源类型划分的本地 HTTP API，提供列表、详情、新建、更新、删除、导入预览、导入提交和检查操作。Tool 不进入可写资源集合。

导入预览不保存配置；提交携带同一份来源内容及用户选择，服务端再次校验后写入，避免为预览引入常驻任务或数据库。检查使用请求生命周期内的异步操作，支持超时和取消，不引入消息队列。

输入错误返回字段路径与原因；资源不存在、版本冲突、文件读写失败分别报告。连接失败、需认证和不支持属于检查结果，不能吞掉异常后返回“成功”。未知程序错误由统一入口记录脱敏日志，前端保留编辑内容并展示可理解的信息。

开发时前端通过 Vite 代理访问后端，生产构建由本地后端提供静态文件。服务默认只绑定本机回环地址，不开放未认证的远程访问；没有产品登录界面。

## 9. 验收与交付

| 验收项 | 必须看到的结果 |
| --- | --- |
| 基础闭环 | 五类资源可新增或导入、读取、修改、删除；页面刷新与服务重启后内容一致 |
| 导入校验 | 合法 mcpServers JSON 可预览和保存；非法 JSON、错误 args 或 env 类型、缺必填字段有具体错误 |
| Skill | 带配套材料的目录或 ZIP 可完整导入，包内相对引用保持；无效清单与越界路径被拒绝 |
| 配置与检查分离 | 保存或导入不自动连接服务；修改配置后旧检查结果不会被当成新版本的证明 |
| 真实检查 | 使用受控 MCP 服务与模型 HTTP 测试端点验证成功、认证失败、超时和取消，而非只模拟返回值 |
| 平台检测 | 三种适配器各自处理可见、未安装和可查询的认证状态；真实环境无法验证的部分明确列出 |
| 凭据 | 保存后可继续用于检测，普通 API、预览与日志均不泄漏私密值 |
| 文件保存 | 写入失败不损坏旧配置；冲突修改和批量部分失败有明确结果 |
| 界面 | 左侧分类、右侧列表和编辑区可用，导入预览与结果清楚，Tool 显示暂未开放 |

实施时补齐实际可运行的前端构建、类型检查、后端检查和相关测试命令。对保存、导入和进程连接边界编写有意义的测试，不给每个简单转发或展示函数机械补测试。通过浏览器核对页面、表单、导入和错误反馈，并在收尾进行对抗性审查。

本阶段完成后交付可启动的前后端、配置文件示例、真实启动与验证说明、已验证的平台范围及剩余限制。随后再讨论画布和执行模块，不提前创建运行状态与并发调度实现。
