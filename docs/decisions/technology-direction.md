## 当前范围

用户选择以 TypeScript 前端和 Python 后端推进 AsomForge，当前任务仅生成目录与说明文档。具体框架、库、版本和运行工具尚未安装或验证。

## 2. 后续评估的技术建议

| 部分 | 建议 | 选择理由 | 状态 |
| --- | --- | --- | --- |
| 前端框架 | React | 适合交互式管理界面与自定义节点 | 待确认 |
| 前端构建 | Vite | 独立构建静态前端 | 待确认 |
| 画布 | React Flow | 提供节点与连线交互基础 | 待确认 |
| 后端框架 | FastAPI | API、数据校验与事件响应 | 待确认 |
| 数据结构校验 | Pydantic | 后端输入输出与业务契约校验 | 待确认 |
| 数据访问 | SQLAlchemy | 关系型持久化访问 | 待确认 |
| 数据库迁移 | Alembic | 后续结构变更记录 | 待确认 |
| 前端包管理 | pnpm | 管理前端依赖和锁文件 | 待确认 |
| 后端环境管理 | uv | 管理 Python 环境、依赖和锁文件 | 待确认 |
| 接口类型衔接 | 基于 OpenAPI 生成前端接口类型 | 减少双语言手工维护差异 | 待确认具体工具 |
| 单实例数据库 | 优先评估 SQLite | 降低本机安装负担 | 待确认并发和部署要求 |

SQLite 与 PostgreSQL 的事务、锁和运行特性不同。如需支持两种数据库，应分别验证；不把 ORM 当作可以无成本切换数据库的保证。

## 4. 依赖引入原则

后续确定工具链时再创建依赖清单与锁文件。当前不创建空的或无法运行的依赖配置，不提供未经验证的启动命令。

依赖产品能力与内部任务模型应保持清楚边界：框架接入不能改变用户配置协作、平台交接产物、无首版自主分派与长期记忆的约定。
